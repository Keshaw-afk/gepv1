# GEPV1 — Minimal Architecture

**GEPV1 (General Environment Programming Engine V1)**: a teacher draws a stage with drag and
drop, writes a short Lua script that drives it, and gets a video.

This document describes a **deliberately small V1**: just enough to run one example end-to-end
and show every step of the process. Source notes: [`idea.txt`](idea.txt).

---

## 1. Scope

**In V1**
- **GUI editor (web page):** drag and drop nodes and edges, then save the stage
- **GUI steps:** build simple behaviour without code (colour, move, pause; in sequence or together)
- Shapes: `circle`, `line`, `text`
- Lua API: `node`, `edge`, `color`, `move`, `wait`, `neighbors`, `edge_of`
- In-page preview (play / scrub) and a trace of every pipeline stage
- Output: **MP4 video** (SVG frames encoded by ffmpeg), **animated SVG** (one self-playing file),
  and a still SVG of any frame

**Not in V1:** forces/physics, plugins, loops/conditions in the GUI steps, LLM translation.

**Technology:** JavaScript (ES modules) for the engine and the web page; Lua runs in the
**Fengari** VM (Lua 5.3 written in JS), so the same engine code runs in the browser and in Node.

---

## 2. Pipeline

```
 GUI editor ──► stage.lua  ─┐                                                ┌─► SVG frames ─► MP4
 GUI steps  ──► steps.lua  ─┼─► Lua API ─► Commands ─► Timeline ─► Player ───┤   (ffmpeg)
 teacher    ──► script.lua ─┘   (Fengari)  (records)   (sorted, t)  (scene at t)└─► animated SVG
```

Each stage has a single, inspectable output, and the **trace** prints what each one produced.
That makes the demo easy to explain.

| Stage | Input | Output |
|-------|-------|--------|
| **GUI editor** | teacher's drag and drop | `stage.lua` (plain API calls) |
| **GUI steps** | clicks, colour picks, drags | `steps.lua` (plain API calls) |
| **Lua API** | `stage.lua` + `script.lua` | calls such as `color(A, "red")` |
| **Commands** | API calls | data records `{op, id, prop, value, t, dur}` |
| **Timeline** | commands | commands in start-time order, script clock in integer ms |
| **Player** | timeline + time `t` | scene state at `t` (interpolated) |
| **SVG renderer** | scene state | one SVG document per frame |
| **Video export** | SVG frames | `out.mp4` |
| **Animated SVG** | timeline (resolved tweens) | one `.svg` with `<animate>`/`<set>` elements |

## 3. Core ideas

**Object = properties + API** *(from idea.txt)*
Every shape is an object with an `id` and properties (`label`, position, `color`).
Scripts change objects only through the API.

**One backend for the GUI and scripts** *(from idea.txt)*
The editor does not have its own file format. It saves the stage as **Lua code made of the same
API calls a teacher would write**, and loading a stage means running it:
```lua
-- stage.lua (generated by the GEPV1 editor)
A = node("A", 100, 180)
B = node("B", 270, 90)
C = node("C", 270, 270)
D = node("D", 440, 180)
edge(A, B)
edge(A, C)
edge(B, D)
```
Labels that aren't safe Lua names (spaces, keywords, API names, duplicates) get a variable
such as `node_1`. The label itself is kept as a string.

**GUI steps are code too** *(idea.txt: "define the behaviour we want using GUI, and leave the code
part to the system")*. The Steps tab keeps a list of steps and generates `steps.lua`; the engine
runs stage.lua → steps.lua → script.lua in one Lua state, one clock:
```lua
-- steps.lua (generated by the GEPV1 steps editor)
color(A, "red", 0.5)
color(edge_of(A, B), "red", 0.5); wait(0.5)   -- "with previous": one shared wait
move(B, 403, 40, 0.5); wait(0.5)
```
While building steps, the canvas shows the stage *after* the steps, computed by the same engine.

**Record, then play**
A script runs instantly, but the animation takes time. So API calls don't draw anything.
They append commands to a timeline at the current *script clock*:
- Verbs (`color`, `move`) start at the current clock and last `dur` seconds (default 0.5 s).
- `wait(t)` advances the clock by `t`.

The player then computes the scene at any time `t`:
`scene(t)` = every command whose start time is `≤ t`, applied in order. A command that is
still in progress is interpolated: colours blend and positions move linearly. A new tween
starts from wherever the property currently is.

## 4. Components

```
core/      shared engine (no DOM, no Node APIs; runs in browser and Node)
node/      CLI, local web server, video export
web/       editor page
examples/  stage.lua, dfs.lua, bfs.lua, packets.lua, sort.lua
test/      node:test suites
```

| File | Responsibility |
|------|----------------|
| `core/scene.js` | Objects (nodes, edges), `neighbors`, `edgeOf`, delete with edge cleanup |
| `core/timeline.js` | Command list + script clock (integer ms) |
| `core/player.js` | `sceneAt(timeline, t)`: apply and interpolate commands; frame times |
| `core/svg.js` | Render a scene state as SVG (frames, preview and editor all use it) |
| `core/lua_api.js` | Fengari VM; binds the Lua API; errors as `script.lua:LINE: message` |
| `core/stage_file.js` | Editor scene → `stage.lua` |
| `core/steps.js` | GUI steps → `steps.lua`; drop steps of deleted objects |
| `core/animated_svg.js` | Timeline → one self-playing SVG (same tweens as the player) |
| `core/trace.js` | Readable report of every pipeline stage |
| `node/export.js` | Write SVG frames; encode MP4 with ffmpeg |
| `node/cli.js` | `stage.lua script.lua --trace --video out.mp4 --svg out.svg` |
| `node/server.js` | Serves the page; `POST /api/export` runs the engine + ffmpeg (localhost only) |
| `web/editor.js` | Stage mode: mouse/keyboard → scene edits. Behaviour mode: select, drag → move step |
| `web/app.js` | Tabs (Stage → Behaviour → Result), steps list, code, preview, downloads |

**Script safety:** only Lua's base, table, string and math libraries are loaded (no `io`, `os`,
`require`, `dofile`). An instruction limit stops infinite loops so they can't freeze the page.

**GUI editor actions**

| Action | Result |
|--------|--------|
| Click empty canvas | Add a node (auto label `A`, `B`, …) |
| Drag a node | Move it |
| Shift-drag or right-drag from one node to another | Add an edge |
| Double-click a node / edit the Label field | Rename it |
| `Delete` key or Delete button | Remove the selection (a node's edges go with it) |
| `Ctrl+S` / `Ctrl+O` | Save or load `stage.lua` |

The Stage tab only edits the **initial layout**. Behaviour (what happens over time) comes from the
Steps tab (simple sequences) and/or `script.lua` (loops, algorithms).

**Animated SVG:** each resolved tween becomes an `<animate>` (an instant change becomes a `<set>`).
A move animates the circle, its label and the ends of every edge touching it; objects created
later start hidden. When animations overlap, the later one wins, as in the player. It was checked
in Chrome against the player at 20 ms steps for every example. It plays once.

**Video export:** ffmpeg, with no custom encoder. ffmpeg's built-in librsvg decoder reads the
SVG frames directly:
```sh
ffmpeg -framerate 25 -i frame_%05d.svg -c:v libx264 -pix_fmt yuv420p out.mp4
```
The canvas is 640×360. Its size must be even, because the H.264 / `yuv420p` encoder
requires even dimensions. Each frame has an opaque white background, because otherwise
transparent areas encode as black.

## 5. Lua API (complete V1 surface)

```lua
node(label, x, y)      -- create a circle with a text label; returns id
edge(a, b)             -- create a line between two nodes; returns id
color(id, c, dur?)     -- animate colour to c ("red", "#ff0000", ...)
move(id, x, y, dur?)   -- animate position to (x, y)
wait(t)                -- advance the script clock by t seconds
neighbors(id)          -- list of nodes connected to id (edges are undirected, creation order)
edge_of(a, b)          -- id of the edge between a and b, or nil
print(...)             -- shown in the trace
```

With `neighbors` and `edge_of`, a script works on **whatever graph the teacher drew in the
GUI**. The algorithm doesn't need its own copy of the graph.

## 6. Demo example: DFS on a 4-node graph

**Step 1: draw in the GUI.** Place nodes A, B, C, D, connect A–B, A–C, B–D. This is the
`stage.lua` shown in §3, and the page starts with it loaded.

**Step 2: write the behaviour.** `examples/dfs.lua`:
```lua
local visited = {}
local function dfs(v)
  visited[v] = true
  color(v, "red"); wait(0.5)
  for _, n in ipairs(neighbors(v)) do
    if not visited[n] then
      color(edge_of(v, n), "red"); wait(0.3)
      dfs(n)
    end
  end
  color(v, "black"); wait(0.3)          -- finished
end
dfs(A)
```

**Step 3: run.** Press **Run**, then **Export video** in the page, or from the CLI:
`node node/cli.js examples/stage.lua examples/dfs.lua --trace --video out/dfs.mp4`
```
[stage]     4 nodes, 3 edges (from stage.lua)
[commands]
  t=0.00  create node A (100,180)
  …
  t=0.00  set A.color -> red  dur=0.50
  t=0.50  set A-B.color -> red  dur=0.50
  t=0.80  set B.color -> red  dur=0.50
  …
[timeline]  18 commands (7 create, 11 set), total 4.30 s
[player]    t=0.25  A.color = #d98381  (halfway to red)
[svg]       108 frames at 25 fps
[video]     out/dfs.mp4 (ffmpeg)
```
This is actual output, and the test suite checks these numbers.
